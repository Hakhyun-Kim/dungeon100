# AI 활용 기술 문서 — 이 게임은 어떻게 만들어졌나

> **한 줄:** 사람은 *재미의 방향*만 말하고 — 설계·구현·밸런싱·검증·배포는 AI(Claude Code)가 한다.
> 그리고 그 검증은 릴리스 후에도 멈추지 않는다. **매일 밤 봇이 스스로 이 게임을 플레이한다.**

『백층 던전』은 장르 선정부터 배포까지 전 과정을 AI와의 대화로 만든 3D 로그라이크입니다.
이 문서는 "AI를 썼다"는 주장 대신 **저장소에서 직접 확인할 수 있는 장치와 실측치**로 그 과정을 설명합니다.

- 🎮 플레이: https://hakhyun-kim.github.io/dungeon100/ (설치·로그인 없음)
- 🎬 게임을 직접 할 시간이 없다면: 타이틀의 **「🎬 자동 시연 보기」** (자막 포함 약 2분, 상시)
- 📖 개발 일지(커밋·대화 기반 차트): https://hakhyun-kim.github.io/dungeon100/journal.html

## 1. 사용한 도구

| 도구 | 용도 |
|---|---|
| **Claude Code** (Anthropic) | 유일한 개발 도구. 기획 컨설팅·설계·코딩·집필·밸런싱·브라우저 자동화 검증·CI 구성·문서 작성 |

단, "Claude Code 하나"라기보다 **주기와 권한이 다른 세 층위의 에이전트**로 구성돼 있습니다(대화형 세션 · CI 봇 · 주간 회고 에이전트). 여기에 이 프로젝트에서 얻은 규칙을 직접 만든 **Claude Code 플러그인 + MCP 서버**로 물립니다 → [7장](#7-ai-에이전트-구성--이-게임을-만든-것은-대화-하나가-아니다).

이미지·사운드 **생성** AI는 쓰지 않았습니다. 그래픽은 절차 생성 지오메트리와 캔버스 텍스처, 사운드는 Web Audio 합성 코드이고, **그 코드 역시 Claude Code가 썼습니다.** 산출물이 전부 텍스트(코드)라서 AI가 다시 읽고 고치고 자동 검증할 수 있다는 것이 이 선택의 이유입니다.

## 2. AI가 매 세션 같은 맥락에서 일하게 만드는 장치 — `CLAUDE.md`

세션은 끊기지만 프로젝트는 이어집니다. 그래서 저장소 루트의 [`CLAUDE.md`](../CLAUDE.md)를 **AI의 상시 컨텍스트**로 유지합니다. 이 문서가 이 프로젝트의 실질적인 운영체제입니다.

- **다음 후보(우선순위)** — 무엇을 할지. 각 후보에 *실측 근거*가 붙는다("아레나 클리어율 11/11 = 100% → 상향 필요").
- **구조** — 파일이 어디에 뭐가 있는지. 코드를 고치기 전에 읽는다.
- **원칙** — 리소스·아키텍처·커밋 규칙.
- **완료 노트** — 무엇을 했는지가 아니라 **왜 그렇게 했는지**. `⚠️` 표시가 붙은 줄은 전부 실제로 한 번 당한 함정이고, 다음 세션이 같은 곳을 다시 밟지 않게 하는 장치입니다.
- **세계관 정답지** — "던전 = 쓰이다 만 책 / 마을 = 서문 / 촌장 = 작가 / 100층 문 = 뒤표지". 인트로·벽의 글귀 26개·기억 16개·엔딩이 전부 여기로 수렴합니다. 텍스트를 누가 언제 쓰든 세계관이 흔들리지 않는 이유입니다.

> 반복될 규칙은 대화가 아니라 문서로 승격합니다 — "이 규칙을 CLAUDE.md에 넣어 계속 지켜줘"가 이 프로젝트에서 가장 자주 쓴 지시입니다.

## 3. 무엇을 만들지 고르는 기준 — 3-Gate

새 기능은 세 관문을 통과해야 채택합니다. 매력적이어도 통과 못 하면 보류합니다.

| 관문 | 질문 | 통과 예 | 탈락 예 |
|---|---|---|---|
| ① **절차성** | 코드(시드 RNG·수학·캔버스·Web Audio)로 만들 수 있는가 | 절차 생성 층, 합성 효과음 | 손그림 스프라이트가 필수인 연출 |
| ② **재미** | 코어 루프에 *결정*을 더하는가, 장식인가 | "제단에 체력을 바칠까" | 화면 구석의 정적 배경 |
| ③ **검증가능** | 봇이 자동으로 측정할 수 있는가 | 사망 층 분포, 봉우리당 체력 손실 | 수치화 불가능한 "감성" |

이 게임의 **장르 자체**가 이 기준으로 정해졌습니다 — "AI로 잘 만들 수 있는 게임이 뭘까"라는 질문에 AI가 *"복잡성이 에셋이 아니라 코드에 있는 게임"* 이라는 기준을 제시했고, 거기에 가장 맞는 절차 생성 로그라이크를 골랐습니다.

## 4. 자동 검증이 가능하도록 만든 아키텍처

자동화는 나중에 붙이는 게 아니라 **구조가 허락해야 가능**합니다. 세 가지가 전제였습니다.

1. **로직과 렌더의 분리** — 게임 규칙을 렌더러를 모르는 순수 함수로 유지. 그래서 지형 생성기는 **브라우저 없이** 검사할 수 있습니다(`npm run floor-check`, 300개 층을 1초에).
2. **시드 결정론** — 모든 난수는 `mulberry32` 시드 RNG. **층 번호 = 시드**라 "같은 층은 항상 같은 구조"이고, 버그 재현과 회귀 비교가 성립합니다. 일일 던전은 *날짜*가 시드라 모두가 같은 맵에 도전합니다.
3. **절차 생성이 기본값** — 복잡성을 파일이 아니라 코드에 둡니다. 바이너리가 늘수록 AI가 스스로 고치고 검증할 수 있는 범위가 줄어들기 때문입니다. (규칙과 그 예외 처리는 → [`docs/ASSETS.md`](ASSETS.md))

### ⚠️ 생성기를 갈아 끼울 때의 함정 (동굴 층에서 실측)

새 지형(셀룰러 오토마타 동굴)을 추가하며 확인한 규칙들 — 그대로 [`docs/DESIGN.md`](DESIGN.md#절차-생성-확장의-안전-규칙-2026-07-25-동굴-층에서-확립)에 못 박아 뒀습니다.

- **분기 판정을 메인 난수 스트림에서 뽑지 말 것.** "이 층은 동굴인가?"를 게임의 `rand()`로 한 번이라도 뽑으면 이후 모든 난수가 한 칸씩 밀려 **동굴이 아닌 층까지 전부 다른 맵**이 됩니다. → 별도 스트림으로 판정. 검증은 변경 전후 **180개 층의 지형 해시·배치 좌표 100% 일치**를 확인하고서야 커밋.
- **연결성의 정의를 길찾기와 일치시킬 것.** BFS가 4-연결이면 지형의 최대 연결 영역도 4-연결로 골라야 합니다. 대각선으로만 이어진 통로는 지도상 '길'로 보이지만 실제로는 못 지나가고, 그 층에서 봇이 영원히 갇힙니다.
- **면적이 바뀌면 밀도를 보정할 것.** 동굴은 1.65배 넓어서 같은 수의 적을 두면 난이도가 조용히 내려갑니다 — '바닥 100칸당 적'을 맞췄습니다(동굴 9.77 / 방-복도 10.07).

## 5. ★ AI가 자기가 만든 게임을 직접 플레이하며 검증한다

이 프로젝트에서 가장 특징적인 부분입니다. AI가 **자기 게임을 스스로 구동·조작·측정할 수 있는 하네스를 직접 설계·구현**했습니다.

### 5.1 하네스 (헤드리스에서 게임을 살려 두는 장치)

| 장치 | 왜 필요한가 |
|---|---|
| `?rafshim` | 숨김 탭에서 브라우저가 `requestAnimationFrame`을 멈춘다 → 타이머 구동 rAF + ResizeObserver 폴리필로 대체. **없으면 3D가 아예 부팅되지 않는다** |
| `window.__pump(n)` | 크롬의 집중 스로틀링(오래 숨긴 탭은 타이머가 분당 1회)과 무관하게 **프레임을 동기적으로** 밀어 주는 결정적 스텝 실행기 |
| `__d100` / `__d100run` / `__d100arena` / `__d100town` / `__d100app` | 던전·미니게임·아레나·마을·층 점프의 상태 조회/조작 훅. 프로덕션 빌드에서는 자동 제외(배포판은 `?debug` 게이트) |
| `__d100shot()` | 렌더된 WebGL 캔버스를 PNG로 회수 → **AI가 실제 픽셀을 보고** 블룸·색·대비를 판단 |
| 고정 dt(`__d100fixdt`) | 소프트웨어 렌더링으로 FPS가 낮아도 게임 속도가 일정 |

### 5.2 밸런스 봇 — 실제 게임을 처음부터 자동 플레이

`src/dev/simBot.ts` (1,002줄, DEV 전용 · 프로덕션 번들 미포함)가 **1층부터 실제 게임을 그대로 플레이**합니다. BFS로 미로를 주파하고, 탄막에 수직으로 회피 기동하고, 두 문 달리기는 정답 문으로 조향해 통과하고, 포털·드래프트·마을 선택지를 스스로 진행합니다. N판을 돌리면 **사망 층 분포 리포트**가 나옵니다.

**프로필을 둘로 나눈 것이 핵심입니다.**

| 프로필 | 역할 | 규칙 |
|---|---|---|
| `hard` | **기준선 전용** — 회귀를 재는 고정된 자 | 기준선을 뜬 뒤 **행동 동결**. 출구로 직행, 상자 안 열고, 이벤트 전부 거절 |
| `human` | 체감 난이도 측정 | 상자를 먼저 들르고, 드래프트를 화면 정보로 점수화해 고르고, 방 이벤트를 상황으로 판단 |

> 봇의 행동을 나중에 똑똑하게 고치면 기준선이 무의미해집니다 — 분포가 바뀐 게 *게임 변경 때문인지 봇 변경 때문인지* 구분할 수 없기 때문입니다.

사람형 봇의 설계 원칙은 **"봇에게 사람이 못 보는 정보를 주지 않는다"** 입니다. HUD의 체력 텍스트, 드래프트 카드의 진화 힌트 칩, 희귀도 테두리처럼 **플레이어가 화면에서 실제로 읽는 것**만 파싱해 판단합니다. 대신 '지도를 읽는 능력'(BFS)은 허용합니다 — 사람도 미니맵을 보고 "저기까지 갈 만한가"를 가늠하니까요. 그래서 "제한 시간 안에 출구까지 갈 수 있나?"를 *실제 경로 거리 ÷ 이동 속도*로 판단합니다.

**실측이 말해 준 것:** 같은 게임을 기준선 봇은 6·9층에서 끝내는데, 사람형 봇은 12층 캡까지 3판 전부 무사(평균 아이템 46.7개)했습니다. **기준선은 체감 난이도가 아닙니다.** 기준선은 회귀 탐지용 자로 쓰고, "이 게임이 어렵나?"에는 사람형 수치로 답해야 합니다.

### 5.3 브라우저 없이 도는 검사 — 가장 자주 돌릴 수 있는 방어선

```bash
npm run floor-check
```

300개 층(기본 시드 + 일일 시드 2종)을 **1초 안에** 생성해 6가지 불변식을 검사합니다 — 시작점에서 출구·상자·제단·비밀 문이 **전부 도달 가능한가**, 배치물이 벽 속에 박히지 않았는가, 플레이어 반경으로 실제로 **설 수 있는가**, 고립된 바닥 영역이 없는가, 면적당 적 밀도가 정상인가, 갈림길 포털이 출구에서 3~5칸에 있는가. 새 지형·새 배치물을 넣을 때 **"봇이 갇히는 층"을 커밋 전에** 걸러 냅니다.

```bash
npm run assets-check   # 리소스 규칙을 코드가 지킨다
```

런타임 트리의 바이너리 리소스 · 코드가 실제로 로드하는 외부 호스트 · 직접 의존성 라이선스 · 문서와 원장의 일치를 대조해 어긋나면 실패합니다. **배포 게이트에 편입**돼 있어 원장에 없는 것이 섞여 들면 배포가 멈춥니다. 위반을 일부러 주입해 **실제로 빨간불이 되는 것까지 확인**했습니다 — 통과만 하는 게이트는 죽은 장치이기 때문입니다.

### 5.4 눈과 귀도 자동으로 잰다

- **그래픽** — 헤드리스에서 캔버스를 PNG로 회수해 **AI가 픽셀을 직접 보고** 판단합니다. 예: 카메라 셰이크를 걷어낸 뒤 "정말 카메라가 안 움직이는가"를 프레임 diff로 확인 → 변화 픽셀이 92만 중 1.9천(0.2%)이고 그 분포가 플레이어 중심 반경 57~70px에 몰려 있음(= 화면 전체가 아니라 발밑 파문만 변함).
- **사운드** — 헤드리스에서는 소리를 들을 수 없으니 **노드를 셉니다.** 페이지 스크립트보다 먼저 `AudioContext.prototype`을 감싸 오실레이터·버퍼·컴프레서 생성을 세고, 1층 도달 시점에 **컴프레서가 정확히 1개**(= 마스터 버스가 하나로 수렴했나)와 **소리가 실제로 났는가**를 단언합니다. 세는 대상은 '구현'이 아니라 **약속**이어야 합니다 — 레시피를 바꿔도 참인 명제여야 게이트가 오래 삽니다.

### 5.5 ⚠️ 검증 원칙 — 전투를 잴 때 순간이동 금지

무리 한가운데나 출구 위로 텔레포트해서 재면 **사람이 절대 만들 수 없는 상황**이 만들어져 결과가 망가집니다. 실측으로 한 번 당했습니다: 출구 위로 순간이동시켰더니 5초를 못 버티고 죽어, 메커니즘이 아니라 **텔레포트를 측정한 꼴**이 됐습니다. 전투가 얽힌 검증은 봇처럼 **실제로 걸어서** 접근합니다.

## 6. 상시 자동화 — 사람이 자는 동안 도는 루프

봇은 "필요할 때 돌리는 도구"였지만, 스케줄에 걸자 **개발 루프 자체가 자율적**이 됐습니다.

| 루프 | 주기 | 하는 일 | 없애는 노동 |
|---|---|---|---|
| **배포 게이트 스모크** ([deploy-pages.yml](../.github/workflows/deploy-pages.yml)) | 푸시마다 | 타입 검사 → 리소스 규칙 → 빌드 → **실브라우저로 첫 방문자 동선 + DEV 훅 심층 검사**. 콘솔 에러 1건이면 배포 중단 | "배포하고 나서 깨진 걸 발견" |
| **일일 봇 실주행** ★ ([daily-ghost.yml](../.github/workflows/daily-ghost.yml)) | 매일 00:15 KST | 오늘의 던전을 봇이 실제로 플레이 → 기록을 **게임 콘텐츠로 커밋**하고 배포 | (노동 제거가 아니라 콘텐츠 생성 — 아래 8장) |
| **야간 밸런스 회귀** ([balance-night.yml](../.github/workflows/balance-night.yml)) | 매일 03:30 KST | 하드런 5판 → 사망 분포를 기준선과 비교, 이탈하면 **이슈 자동 생성** | 손으로는 못 찾는 밸런스 회귀 |
| **문서 데이터 생성** (`npm run journal-data`) | 필요할 때 | git log 분석으로 개발 일지의 통계·차트 데이터를 재작성 | 수기 통계가 조용히 낡는 것 |

### ⚠️ 크론 자동화 5원칙 (전부 실제로 당하고 얻은 것)

1. **멱등하게.** "오늘 기록이 이미 있으면 즉시 종료" — 수동 재실행·중복 트리거에도 안전.
2. **시간대를 두 번 못 박아라.** 크론은 UTC인데 게임의 '오늘'은 KST. 브라우저 타임존을 고정하고, **끝난 뒤 게임이 실제로 기록한 날짜와 파일명을 대조**합니다. 이 검증이 없으면 자정 근처에 하루 어긋난 기록이 조용히 커밋됩니다.
3. **자동 커밋은 다른 워크플로를 깨우지 않는다.** CI 토큰으로 푸시하면 배포 워크플로가 안 돕니다 → 커밋과 배포를 **같은 워크플로 안에서** 이어 붙였습니다.
4. **실패했으면 침묵하라.** 봇이 교착하면 기록을 쓰지 않고 끝냅니다 — **빈 데이터가 틀린 데이터보다 낫습니다.** 폴백이 있으면 플레이어는 아무것도 눈치채지 못합니다.
5. **드리프트는 '실패'가 아니라 '알림'.** 종료 코드를 나눠(비정상 종료 → job 실패 / 기준선 이탈 → 이슈 생성) 진짜 고장과 튜닝 신호가 섞이지 않게 합니다.

### ⚠️ 봇을 CI에서 돌릴 때 (로컬에서 잘 돌던 봇이 Actions에서 멈춘 이유)

- **프레시 프로필 함정** — 개발자 브라우저에는 세이브가 있어 인트로가 건너뛰어집니다. CI 러너는 **항상 첫 방문자**라, "아무 버튼이나 누른다"는 범용 규칙이 인트로의 잠긴 책 퀴즈를 눌러 봇이 영원히 갇혔습니다. → 초기 화면 분기를 범용 규칙보다 **먼저** 명시 처리.
- **줄여야 할 건 로직이 아니라 픽셀** — CI에는 GPU가 없어 소프트웨어 렌더러로 돕니다. 그대로 두면 1판에 30분. **뷰포트를 640×360으로 줄이고 저품질 모드를 강제**하면(렌더 전용 설정이라 밸런스는 불변) 같은 5판이 16분입니다.
- **에러 필터 규율** — "콘솔 에러 0건" 게이트는 by-design 404(파비콘, 있으면 쓰고 없으면 폴백하는 선택적 리소스)를 반드시 제외해야 합니다. 안 그러면 게이트가 늘 빨간불이고, 사람은 곧 그것을 무시합니다.

## 7. AI 에이전트 구성 — 이 게임을 만든 것은 대화 하나가 아니다

작업 주기가 다른 **세 층위의 에이전트**가 각각 다른 권한으로 돕니다. 권한을 층위별로 좁혀 둔 것이 핵심입니다.

| 층위 | 무엇을 하나 | 주기 | 쓰기 권한 |
|---|---|---|---|
| **대화형 세션** | Claude Code — 설계·구현·검증·배포 | 사람이 부를 때 | 저장소 전체 |
| **CI 봇** | 배포 스모크 · 야간 밸런스 회귀 · 일일 실주행 | 푸시 / 크론 | 기록 JSON·이슈만 |
| **회고 에이전트** | 게임들의 변화를 읽고 방법론 문서에 교훈 승격 | 매주 | 플레이북 저장소만 (게임 저장소는 읽기 전용) |

### 7.1 방법론을 Claude Code 플러그인 + MCP 서버로 추출

이 게임에서 얻은 규칙들 — "봇 프로필을 기준선용과 사람형으로 나눠라", "긴장을 사망률로 재지 마라", "생성기를 갈아 끼울 땐 난수 스트림을 분리하라" — 은 대화가 끝나면 사라집니다. 그래서 **에이전트가 필요할 때 조회할 수 있는 형태**로 저장소 밖에 뽑아 두고, 공개 배포했습니다.

> 📦 **[agentic-gamedev-playbook](https://github.com/Hakhyun-Kim/agentic-gamedev-playbook)** — v1.21.0 · MIT · **런타임 의존성 0** · 15개 장
> 「AI가 만들고 AI가 검증하는」 게임 개발 방법론을 **Claude Code 스킬 + MCP 서버** 한 벌로 묶은 것.

```bash
# ① 플러그인(스킬 + MCP 서버)으로 설치
/plugin install agentic-gamedev@agentic-gamedev-playbook

# ② MCP 서버만 단독 연결
claude mcp add gamedev-playbook -- npx -y github:Hakhyun-Kim/agentic-gamedev-playbook
```

| 형태 | 제공하는 것 | 언제 물리나 |
|---|---|---|
| **스킬** (`agentic-gamedev`) | 실행용 요약 — 3-Gate·아키텍처 규약·봇·게임필 체크리스트 | "게임 만들어줘", "밸런스 맞춰줘" 같은 요청에 **자동으로** |
| **MCP 도구** | `playbook_toc` · `playbook_section {query}` · `playbook_checklist` · `playbook_full` | 필요한 **장만 골라 읽을 때** |
| **MCP 프롬프트** | `/new-game {concept}` · `/balance-tuning` · `/quality-pass` | 새 프로젝트를 그 자리에서 부트스트랩할 때 |

**왜 두 형태인가**: 스킬은 요청에 자동으로 물리는 *실행용 요약*이고, MCP 도구는 15개 장 중 그때 필요한 절만 가져오는 *참조 창구*입니다. 문서 전문을 매번 컨텍스트에 밀어 넣지 않고도 규율이 유지됩니다.

**문서도 코드처럼 빌드·검증합니다** — 단일 진실 원천은 장별 파일(`skills/agentic-gamedev/references/<장>.md`)이고 합본 `PLAYBOOK.md`는 **생성물**이라 직접 고치면 테스트가 실패합니다. 버전은 `package.json`·플러그인 매니페스트·MCP 서버 세 곳이 일치해야 통과합니다. (이 게임의 `assets-check`가 「원장 = 원본, 표 = 생성물」인 것과 같은 규율입니다.)

### 7.2 ★ 되먹임 루프 — 게임이 방법론을 고치고, 방법론이 다음 게임을 만든다

`npm run retro`가 **주간 회고 에이전트**를 헤드리스(`claude -p`)로 띄웁니다. 지난 한 주 동안 여러 게임 저장소(이 게임 · 용사 수학 디펜스 · 두 문 러너 등)에서 일어난 변화를 읽고, **플레이북에 승격할 만한 교훈만** 문서에 반영합니다.

- **지시서가 저장소 안에 있다** (`RETRO.md`) — 문서를 고치는 주체의 규율이 스케줄러 설정에 숨어 있으면 리뷰도 diff도 안 되기 때문입니다. 프롬프트를 고치면 그다음 회고부터 바로 반영됩니다.
- **게임 저장소는 읽기만** — 쓰기 권한은 플레이북 저장소에만.
- **멱등** — 이번 주 회고 커밋이 이미 있으면 즉시 종료.
- **게이트** — 회고는 커밋만 하고, 테스트를 통과한 커밋만 스크립트가 민다.
- **침묵** — 교훈이 없으면 아무것도 커밋하지 않는다. **빈 주는 정상입니다.**

이 게임에서 플레이북으로 실제 승격된 교훈: **봇 프로필 분리**(기준선 동결) · **"긴장은 사망률로 못 잰다"** · **생성기 교체 5원칙**(난수 스트림 분리·연결성 정의 일치·밀도 보정 등) · **CI 함정 셋**(프레시 프로필·픽셀을 줄여라·에러 필터 규율) · **크론 5원칙**.

> 즉 이 게임은 방법론의 **첫 검증 사례이자 공급원**입니다. 여기서 당한 함정이 문서가 되고, 그 문서가 다음 게임의 첫 커밋부터 적용됩니다 — 방법론이 특정 게임의 우연이 아니라 **재사용 가능한 틀**이라는 것을 장르·프레임워크가 다른 세 게임(3D 로그라이크 / 3D 디펜스 / 2D 러너)에서 확인했습니다.

## 8. ★ 검증 산출물을 게임 콘텐츠로 승격 — 「🤖 AI 사서」

가장 값진 패턴입니다. 밸런스 봇은 원래 **개발자만 보는 도구**인데, 그 출력을 게임 안으로 들여보내면 그대로 **매일 갱신되는 콘텐츠**가 됩니다.

```
매일 00:15 KST 크론
  → 봇이 '오늘의 던전'(날짜 = 시드)을 실제로 플레이
  → 결과를 public/ghost/<날짜>.json 로 커밋
  → 같은 워크플로가 그대로 배포
        ↓
  게임: 파일이 있으면 실기록, 없으면 추상 모델로 조용히 폴백 (백엔드 0개 유지)
```

플레이어에게는 HUD 층 칩 옆의 `🤖 8` 로 보입니다 — **「AI 사서가 오늘 여기까지 읽었다」**. 추월하면 축하 연출이 뜨고, 게임오버 화면과 공유 카드에도 비교가 남습니다.

실제 기록 예 ([`public/ghost/2026-07-28.json`](../public/ghost/2026-07-28.json)):

```json
{"date":"2026-07-28","floor":8,"result":"death","items":7,"source":"simBot 실주행"}
```

서버도 DB도 없이 매일 바뀌는 경쟁 상대가 생기고, **밸런스를 바꾸면 그 기록도 자동으로 따라옵니다.**

## 9. 데이터가 판단을 뒤집은 순간 — 실측 4건

AI 활용의 값어치는 "빨리 만든다"가 아니라 **사람의 직관이 틀렸다는 걸 수치로 잡아낸다**는 데 있었습니다.

### ① 스노볼 — "파밍 빌드가 무적이 된다"

파밍런(2층마다 전설 보상)을 시뮬레이션했더니 **160아이템으로 61층까지 무저항 순항**했습니다. 적 스탯은 15~21층에서 캡에 걸리는데 아이템은 복리로 쌓이기 때문입니다. → **깊은 층 위협 램프**(30층+ *받는 피해*만 가속. 적 HP를 부풀리면 초반까지 딱딱해집니다) + 스폰 캡 상향으로, 최상급 파밍 가정에서도 가끔만 뚫리는 분포(사망 10·10·15·30층)로 정착. 하드런(평균 8.3층)은 15층 미만이라 **영향 없음**을 함께 확인했습니다.

### ② "긴장"은 사망률로 재면 안 된다

출구 앞 긴장 봉우리(한 층에 한 번, 적이 광폭화하고 포위하며 출구가 잠긴다)를 넣고 봇으로 쟀더니 **11번 중 사망 0**. "전혀 안 먹는다"고 판단해 강도를 올렸는데 또 0사. 여기서 수치를 더 올렸다면 원인도 모른 채 억울한 죽음만 만들었을 겁니다.

대신 **봉우리 한 번당 깎인 체력 비율**을 기록하게 하자 답이 나왔습니다 — 평균 **20.3%**, 최대 **72.7%**(개별 0·5·10·10·11·11·18·18·30·37·73%). 봉우리는 이미 충분히 위협적이었고 **사망만 안 났을 뿐**이었습니다.

> 교훈: 사망률은 이분법이라 '긴장'의 해상도를 못 냅니다. 압박은 **연속량**(잃은 자원 비율)으로 재고, 평균이 아니라 **분포**를 보세요 — 평균 20%에 최대 73%라는 *분산 자체가 좋은 봉우리의 정의*입니다.

### ③ 멀미 신고 — 원인은 셰이크가 아니라 '자동 발사'였다

"몬스터와 싸울 때 카메라가 흔들려 멀미가 난다"는 신고. 카메라 셰이크는 *한 방짜리* 장치인데 이 게임은 **자동 발사**라 명중이 끊이지 않아, 평타마다 흔들림이 누적돼 전투 내내 시점이 진동하고 있었습니다. → 무게를 **시점 이동이 아니라 세계의 반응**으로 옮겨, 맞은 자리에서 퍼지는 **임팩트 파문**으로 교체(히트스톱은 유지 — dt=0은 화면을 움직이지 않습니다). 부수 효과가 아니라 이득도 있었습니다: 셰이크는 화면 전체라 '어디서 터졌는지' 정보가 없는데, 파문은 좌표가 있어 때린 자리와 맞은 자리가 구분됩니다. **검증은 픽셀 diff**(→ 5.4).

### ④ "화면이 한 번씩 더 나온다"는 신고 — 버그가 아니라 의미의 문제

프레임 단위로 화면 전환을 기록해 1~9층을 실제로 걸어서 확인한 결과 **중복 렌더 버그는 없었고**, 그 화면이 뜬 층은 정확히 갈림길이 열린 층뿐이었습니다. 문제는 렌더가 아니라 **의미**였습니다 — 직전에 없앤 '내려갈래?' 확인창과 생김새가 똑같아서, 사용자에겐 *지워졌어야 할 화면이 되살아난 것*으로 읽혔습니다. → 선택을 화면에서 **던전 바닥으로** 내렸습니다(출구 곁의 붉은 포털 — 어느 포털에 몸을 넣는지가 곧 대답). 이 배치는 난수를 한 번도 쓰지 않아 **기존 층 구조가 한 칸도 안 바뀝니다.**

## 10. 프롬프트 / 지시 패턴

### 10.1 실제로 쓴 지시 (원문 요약)

**장르 선정**
> "게임 스케일이 좀 작아 보이는데, AI로 잘 만들 수 있는 게임은 어떤 게 있을까?"

**크로스오버 미니게임의 탄생**
> "보물상자 들어가면 두 문 러너를 하나 풀고 아이템을 얻게 하면 어떨까? 아이템을 얻으면 시각적으로 확실하게 변화를 주고, 타격했을 때도 화면에 확실하게 효과를 줘."
> "미니게임을 좀 더 길게 해주고, 길수록 아이템이 좋아지면 좋겠어." → AI가 **푸시-유어-럭**(문마다 "받고 나가기 vs 더 달리기", 3연속 완주 = 전설) 구조를 제안·구현

**스토리·세계관**
> "어제까지 한국에서 2026년에 살던 대학생 → 던전 책을 보다가 → 자고 일어나니 책에서 보던 마을… 게임이니까 내가 선택해서 무언가를 하는 느낌 (사실 선택은 하나밖에 없지만)."

→ 기획 의도만 주면 AI가 세계관 정답지(던전 = 책)를 설계하고 인트로·마을 대화·기억 16개(네 갈래, 완성 시 능력 각성)·벽의 글귀 26개·엔딩 2종+에필로그를 그 정답지에 수렴하도록 집필했습니다. 위 인용의 *"사실 선택은 하나밖에 없지만"* 은 게임 안에 **가짜 선택 개그**("다른 방법은 없나요?" → "없어.")로 남았습니다.

**위임형 — AI가 스스로 찾고 넣는다**
> "이제 니가 해커톤 심사위원이 되어서 넣었으면 하는 기능을 찾아내고 알아서 넣어줘봐." → 미니맵·처치 콤보·모바일 진동
> "지금 뭔가 재미 요소가 빠진 거 같아서 — 뭐가 비었는지 진단해줘." → **"빌드가 숫자만 키우고 플레이 방식을 바꾸는 잭팟 순간이 없다"** 는 갭 진단 → 진화 「합본」 5종

**증상만 말하기**
> "이동이 뒤로 갈수록 불편해 — 증가량을 1/10로 하거나, 뒤로 갈수록 증가폭을 줄이거나." → 곱연산 성장을 **소프트 캡**(`value += (CAP - value) * 0.15`)으로 교체

### 10.2 패턴 요약

| 패턴 | 왜 효과적인가 |
|---|---|
| **증상만 말하기** | 원인 진단을 AI에 맡긴다. 증상 + 후보 2개면 충분 |
| **위임형** | 사람이 떠올리지 못한 기능이 나온다(미니맵·콤보·진동) |
| **규칙 승격** | "이 규칙을 CLAUDE.md에 넣어 계속 지켜줘" — 세션이 바뀌어도 일관성 유지 |
| **상시 위임(스케줄)** | 일회성 검증을 **매일 도는 루프**로 승격(일일 실주행·야간 밸런스 회귀) |
| **순차 진행 요구** | "순서대로 진행해줘" — 자동화를 한 번에 벌이지 않고 하나씩 실측·검증. 실패 원인이 섞이지 않는다 |
| **"됐다" 전에 실제로 돌려보게 하라** | 이 프로젝트의 교훈 대부분(CI 함정 셋, 시간대·멱등성)은 문서를 쓰다가가 아니라 **실제로 크론을 돌려보다가** 나왔다 |

## 12. 한계 — 아직 AI가 못 잰 것 (정직하게)

자동화의 경계를 명시하는 것도 이 방법론의 일부입니다.

- **체감은 사람만 잴 수 있다.** 카메라 셰이크를 걷어낸 뒤 "멀미가 실제로 가셨는지"는 픽셀 diff로 증명할 수 없습니다. 실기기 확인이 남아 있습니다.
- **발견율.** 새로 만든 붉은 포털을 플레이어가 **모르고 지나치는지**는 실플레이 관찰이 필요합니다(낮으면 나침반 화살표를 추가하는 게 다음 수).
- **헤드리스에서 못 하는 것.** 숨긴 탭은 타이머가 죽어 **자동 시연 2분 전체 재생**은 헤드리스로 검증할 수 없습니다(개별 장면만 `__pump`로 검증). iOS Safari의 오디오 잠금·성능도 실기기 항목입니다.
- **봇은 사람이 아니다.** 회피가 정확하고 자동 조준이 붙어 사람보다 유리할 수 있습니다. 그래서 봇 수치는 *절대 난이도*가 아니라 **변화의 방향**을 재는 데 씁니다.

## 13. 재현 — 명령어 한 눈에

```bash
npm install
npm run dev                 # 개발 서버 (localhost:5175)

npm run typecheck           # 타입 검사
npm run floor-check         # 300개 층 생성 불변식 (브라우저 없이 1초)
npm run assets-check        # 리소스 규칙 (브라우저 없이 1초)
npm run smoke               # 부팅 스모크 — 배포 게이트와 동일
RUNS=3 npm run balance-regression   # 봇 자동 플레이 → 사망 분포 vs 기준선
```

개발 서버 콘솔에서 봇을 직접 돌려볼 수도 있습니다:

```js
__d100sim.start({ runs: 5 })                 // 기준선(하드) 프로필
__d100sim.start({ runs: 3, profile: 'human', maxFloor: 25 })   // 사람형 프로필
```
